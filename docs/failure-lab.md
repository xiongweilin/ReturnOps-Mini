# 故障场景与验收边界

本文记录可复现的故障场景、预期不变量及应取得的证据。实际执行入口及历史结果见 [faultlab](../faultlab/README.md)、[测试证据](TEST-EVIDENCE.md) 和相应集成测试。未实际执行的场景属于待验证验收要求。

| 场景 | 必须保持的行为 | 相称证据 |
| --- | --- | --- |
| 基于同一旧版本并发修改 Case | 同版本的冲突转换不能同时提交 | PostgreSQL 并发测试与版本更新结果 |
| 相同 Idempotency-Key 并发提交 | 相同请求收敛到同一效果；内容冲突拒绝 | 数据库唯一约束、响应及持久记录 |
| 跨租户使用真实 Case ID | 不泄露其他租户对象或修改它 | 不同租户身份的 API/服务测试 |
| 高额退款并发首次审批 | 不能留下两个互不排斥的首次审批 | 持久化审批与 Case 版本的并发检查 |
| Provider 执行前明确失败 | 按已证实失败状态处理，不与 UNKNOWN 混淆 | 受控 503-before-processing 故障场景 |
| Provider 已退款但 ACK 丢失 | 转入不确定状态，不盲目再次 POST | timeout-after-processing 和 provider 查询 |
| Webhook 先成功、超时回调后到 | 已确立的成功不被迟到回调降级 | 乱序回调回归测试 |
| 相同 Webhook 重放 / 内容冲突 | 一致重放幂等；相同事件 ID 的冲突内容拒绝 | Webhook 唯一键与 payload 校验 |
| Worker 在外部效果后、本地提交前终止 | 恢复不重复生成不可控外部退款 | 稳定 provider intent、重启及对账 |
| 未来业务规则与 schema 变化 | 历史记录、规则版本及迁移结果可追踪 | 具体 migration / rollback 验收后方可声明 |

故障注入只改变隔离的演示环境，不应触达真实支付服务或客户数据。不要把“未观察到错误”表述为已经证明不存在危险路径。可核验的运行结果与未验证的验收要求必须分别记录。
